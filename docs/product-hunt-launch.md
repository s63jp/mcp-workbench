## 2. 📝 Product Description (500 chars max)

```
MCP Workbench is a web-based testing platform for Model Context Protocol (MCP) servers — think "Postman for MCP."

Paste a server command, click Connect, and instantly see available tools, test them with a JSON payload editor, and debug via a live JSON-RPC console. No terminal. No config files. No cryptic stdio errors.

Built for developers using Claude, Cursor, VS Code, and Cline with MCP.

✅ Connect to any MCP server instantly
✅ Discover tools and inspect schemas
✅ Test tool calls visually
✅ Debug with live console
✅ Get verification badges: 🟢 Verified / 🟡 Untested / 🔴 Failed

Open source. Free tier. Zero config.
```

## 3. 🗣️ First Comment (The "Maker Story" Hook)

```
Hey Product Hunt! 👋

I built MCP Workbench because I was tired of debugging MCP servers in the terminal.

Here's the problem: there are 1000+ MCP servers on GitHub now, but testing them means:
1. npm install
2. Configure Claude/Cursor
3. Get a cryptic stdio error
4. Debug in terminal
5. Repeat

I wanted something simpler. Something visual.

So I built MCP Workbench — paste your server command, click Connect, and test every tool in your browser with a live JSON console. No terminal. No config files.

The verification engine is what I'm most proud of. It actually runs each server and gives you 🟢 Verified / 🔴 Failed badges with runtime evidence — not "works on my machine" assumptions.

Tech stack: Next.js 16 + React 19 + Python asyncio + WebSocket + Tailwind CSS. Built for £0, fully autonomous.

Happy to answer any questions about MCP, stdio transport, or the verification engine!
```

## 11. 💬 FAQ for Comments

**Q: Is this free?**
A: Yes. Free tier for public server testing. Pro (£9/mo) for private servers, saved configs, and compatibility reports.

**Q: Does it work with [specific MCP server]?**
A: If it speaks MCP stdio, it works. We've tested filesystem, GitHub, memory, and more.

**Q: Is my data safe?**
A: Sessions are isolated. No server-side storage of your MCP connections. Open source — you can audit everything.

**Q: Can I self-host?**
A: Absolutely. Clone the repo, install dependencies, run locally.

**Q: What about HTTP/SSE MCP servers?**
A: stdio is fully supported. HTTP/SSE support is on the roadmap.
